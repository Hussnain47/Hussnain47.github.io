Email template management, extended with AI.

Built email template management with version management and support for concurrent administrator updates, then extended it with multilingual content and AI translation.

ContextProduct engineering · Khoros Community
My roleFull-stack implementation and design decisions
TechnologyReact / TypeScript / Java / GraphQL / LLMs

The problem

Community administrators needed a way to manage email templates, handle versions, and work with concurrent admin updates. Multilingual support then had to build on that workflow without breaking dynamic variables, formatting, or the existing delivery behavior. Asking a language model to preserve an entire HTML document was not a sufficient correctness strategy.

My contribution

I created the base email template-management feature, including version management and support for concurrent administrator updates. I then extended that foundation with multilingual variants, locale-aware resolution, GraphQL operations, and the Aurora editor workflow, followed by AI-assisted translation. The AI work included the editor translation action, undo behavior, and a fallback-model chain in AI Settings.

Build the management foundation first

I built version management and support for concurrent administrator updates into the original editor. That gave the later multilingual and AI features a foundation to build on.

Keep language review separate from publishing

Each template version contains its language variants. Publishing the version publishes those languages together. I kept translation approval separate, so an admin can approve a language without accidentally publishing the whole version.

Keep formatting and variables out of the model’s hands

The translator sends only the text that needs translation to the model. The application keeps control of the document structure. I added checks for markup and placeholders after seeing the model change formatting and translate a variable name. The translated content still needs an admin’s review before it can be used.

Keep existing email delivery working

If a language variant is missing or has not been approved, delivery falls back to the existing translated Handlebars template. It does not quietly send the English version instead. Admins can also edit translations manually when AI is not configured, and the AI settings support a fallback model chain.

Validation and outcome

I connected translation to the editor, fixed an undo issue that left the canvas showing the wrong content, and added the fallback model chain. The earlier backend phase passed 94 orchestration tests, including checks for language resolution and translation approval.

What I learned

AI works better here when its job is limited to translation. The application handles formatting, variables, review, and publishing, so those rules do not depend on the model following a prompt.
