02 / AI engineering practice

How I use AI to build software.

I created a set of reusable AI skills for the way I work: planning a change, building it, testing it, and working through review feedback.

  1. 01

    Architecture & planning

    Understand the codebase, compare options, and agree on a plan before writing code.

  2. 02

    Development

    Build the change in small steps, using the patterns already in the project.

  3. 03

    Testing

    Test what the feature does, including the awkward cases, and check that a broken implementation would fail the tests.

  4. 04

    Review & response

    Review the code, investigate the feedback, and fix the problems that the evidence supports.

Custom orchestration

The review-fix loop

My review-fix-loop skill gives reviewer and fixer agents separate jobs. The reviewer looks for problems. The fixer checks each finding before changing the code. They repeat the process for a limited number of rounds, with another review to confirm the result.

I use mutation testing to check whether tests catch deliberately broken code. An agent passing a review still leaves the final decision with a person.

Root cause before code

Structured bug investigation

For bugs, my skills start by tracing what went wrong. They compare possible causes against the code before proposing a fix, so the change addresses the cause rather than just hiding the symptom.

I built these skills to make good engineering habits easier to repeat. I’m still responsible for understanding the change and checking the result.
